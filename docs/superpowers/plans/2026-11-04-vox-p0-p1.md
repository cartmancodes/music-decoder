# VOX Implementation Plan (P0 foundations + P1 VOX)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ship VOX and VOX Lite (macOS + Windows, closed commercial) at
month 8, meeting every requirement in the VOX spec, with the riskiest
piece (the ≤ 3 ms tuner) proven first.

**Architecture:**
- **Monorepo:** `rapsuite` (private, new), built from pamplejuce with
  JUCE 9.
- **Shared library:** `libs/rapcore` holds DSP, pitch, theory, real-time
  helpers and licensing.
- **Plugin:** `plugins/vox` is the JUCE processor and editor shell.
- **UI:** `ui/vox` is a React app inside the JUCE WebView.
- **Prototype:** the tuner is built first in **this repo**
  (`prototypes/tune`), then moved into `rapcore` once the monorepo exists.
- **Reference code:** Python reference implementations (Auto-Key) live in
  `music_decoder`.

**Tech stack:**
- C++23 for the suite (C++20 in the prototype), CMake ≥ 3.25 with CPM,
  JUCE 9.0.x, clap-juce-extensions.
- Libraries: cycfi/q, signalsmith-dsp and Basics, r8brain, libebur128,
  farbot.
- Tests and validation: Catch2 (suite) / doctest (prototype), pluginval 2,
  RTSan (Clang 20+).
- UI: React + TypeScript + Vite, `@juce-framework/webview`.
- Release: Moonbase, sentry-native, GitHub Actions.

**Spec:** [`docs/superpowers/specs/2026-11-04-vox-design.md`](../specs/2026-11-04-vox-design.md)
(requirement IDs FR-/NFR- referenced below). **Parent:**
[master plan](2026-11-04-rapper-suite-master-plan.md). **Spike results:**
[`docs/reports/2026-11-04-tune-spike-v0.md`](../../reports/2026-11-04-tune-spike-v0.md).

## Global Constraints

- **D1 licence rule:** shipped code may use only MIT, BSD, Apache-2.0,
  ISC, zlib, BSL-1.0, WTFPL or 0BSD, plus MPL-2.0 used unmodified. No GPL,
  LGPL, AGPL or NC code; the CI licence scan fails the build otherwise.
  **Clean-room:** nobody on the DSP team reads zita-AT1, x42, Rubber Band,
  chowdsp GPL modules or Matchering source.
- **Audio thread:** no allocation, locks, syscalls, logging, I/O or
  exceptions. Everything is allocated in `prepare*()`. Verified by RTSan
  builds plus allocation-counter tests.
- **Determinism:** output is identical for any host block size (NFR-6).
  Offline render equals real time (NFR-7). There is no quality switch for
  offline render.
- **Latency is fixed per mode and sample rate** (FR-LAT-1). Bypassed
  blocks are replaced by delay.
- **Parameter IDs are permanent once released.** One definition file
  generates C++, JSON and TypeScript.
- **Every change** keeps CI green: build (macOS universal and Windows
  x64), unit, golden and latency tests, pluginval strictness 10, auval,
  licence scan.
- **Never write "Auto-Tune"** in UI, docs or marketing.
- **This repo** (`music-decoder`) is R&D. It can keep madmom for research,
  but nothing that depends on madmom models is ported.

## Review Focus

- Shifter splice timing when the period estimate jumps (note change
  mid-crossfade): the head must never overtake the write head (test with a
  ratio of 2.0 and a period step).
- Voicing flicker at low f0 (q's update gap): hold ≥ 3.5 periods (spike
  finding 2).
- Mode switch Track ↔ HQ changes the reported latency, which the host
  must re-sync. This must never happen implicitly (e.g. on preset load)
  without the UI notice.
- State migration: sessions from older versions render identically
  (FR-STATE-1).
- WebView keyboard focus: spacebar must reach the host after clicking a
  control (FR-UI-3).
