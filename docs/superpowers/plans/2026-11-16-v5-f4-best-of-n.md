# v5 Feature 4: Generate Many, Keep the Best — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fingerstyle `compose()` writes N = 12 candidates and keeps the best by a pinned symbolic score. The opt-in `--rank-audio` re-ranks the top 4 by a pretrained audio-taste model (Audiobox Aesthetics).

**Architecture:**
- A new `compose/scoring.py` scores an `Arrangement` from our own metrics.
- `arrange(..., candidates: int = 1)` builds the candidates and keeps the best. Candidate 0 uses the caller's seed, so `candidates=1` equals today's output. `compose_with_options(..., candidates=12)` is the product default.
- The audio re-rank lives in a new lazy-import package, `compose/ml/`, behind an optional `ml` dependency group. It never runs in the default path or in the default tests.

**Tech Stack:**
- Python 3.11, numpy and pytest.
- Optional, in the `ml` extra: `audiobox_aesthetics` 0.0.4, `transformers`, `huggingface_hub` (dry-run checked: installs with numpy < 2).
- Weights: `facebook/audiobox-aesthetics` (CC-BY-4.0, about 415 MB).

**Spec:** `docs/superpowers/specs/2026-11-16-composer-v5-design.md` (§5.4, §5.6, §6 items 1, 2, 6 and 8).

- The feature-2 and feature-3 gates stay exactly as they are; their margins are thin (see below). The harness evaluates fingerstyle with `candidates=12`, so all of them are measured on the chosen candidates.
- With the same seed and arguments, output is identical, whatever `PYTHONHASHSEED` is.
- The default path and the default test suite never need the network, the `ml` extra or the weights. ML imports live only under `compose/ml/` and are lazy.
- Gates before each commit: `pytest -q tests/unit`, `ruff check src tests`, `ruff format --check src tests`, `mypy --strict src`. Run `pytest -q tests/integration` at the last task.

- **Thin feature-3 margins (ledger note):** validation F.peak is 0.9012 against 0.9, F.M1 0.9509 against 0.95, A3.fingerstyle on validation/major is 0.1047 against 0.1067, and holdout F.M6 is +1.88 against +1.85. The score includes those metrics, so best-of-12 should raise them. If one still fails, the score weights are this feature's to tune; no other feature's constants change.

## Review Focus

1. **`seed=None`:** a random base seed is drawn once, and candidates 1–11 are derived from it. Two calls differ, but within one call the choice is deterministic. Test: Task 1's `test_seed_none_still_chooses_deterministically_within_a_call`.
2. **`candidates < 1`, or a non-integer:** `ValueError` from `arrange`, `compose_with_options` and the CLI. Test: Task 1's `test_candidates_must_be_at_least_one`.
3. **The ML extra not installed, or weights missing, with `--rank-audio`:** a clear error naming `pip install -e ".[ml]"` and `music-decoder fetch-models --composer-models`. No traceback from deep inside torch. Test: Task 2's `test_rank_audio_without_the_extra_explains_how_to_install`.
4. **`--rank-audio` with strum or arpeggio:** it is ignored, with `metadata["rank_audio"] = False`, and no model is loaded. Test: Task 2's `test_rank_audio_is_fingerstyle_only`.
5. **Very short pieces (1 bar):** every candidate may be identical. Ties go to the lowest k, and k = 0 wins. Test: Task 1's `test_ties_choose_the_first_candidate`.

**Interfaces:**
- Consumes the metrics in `compose/metrics.py`:
  - `bar_identity`, `melody_above_accompaniment_ratio`, `strong_beat_chord_tone_ratio`, `step_ratio`, `repeat_ratio`, `ioi_entropy`, `ambitus`;
  - `leap_recovery_counts`, `motif_contour_match`, `hook_restatements`, `peak_uniqueness`, `contour_arch`, `shape_moves`.
- Produces:
  - `score_arrangement(arr: Arrangement, progression: Sequence[ChordSymbol], *, bars_per_chord: int, tempo_bpm: float, tuning: Tuning) -> float`.
  - `arrange(..., candidates: int = 1)`, fingerstyle only.
    - Candidate k's seed is `seed` for k = 0, and `int(np.random.SeedSequence([seed, k]).generate_state(1)[0])` for k ≥ 1.
    - With `seed is None`, draw `base = int(np.random.default_rng().integers(2**31))` once and use it as `seed`.
    - The best score wins; ties go to the lowest k.
  - `Arrangement` gains `candidates: int = 1`, `chosen_candidate: int = 0` and `score: float | None = None`. `score` is set only for fingerstyle.
  - `compose_with_options(..., candidates: int = 12)` passes it to `arrange`.
  - `metadata` gains `candidates`, `chosen_candidate`, `score`, `final_fallback` and `identity_misses` (as a list).
  - CLI: `compose --candidates INTEGER` (default 12).
  - Harness: fingerstyle `Case`s are built with `candidates=12`, and `F.score` comes from `case.fingerstyle.score`.

**Pinned score.** A term whose metric is `None` contributes its neutral value, shown in brackets.

| Weight | Term |
|---|---|
| +3.0 | P3: share of bars meeting `bar_identity` on the accompaniment |
| +1.0 | A2 (`melody_above_accompaniment_ratio`) [1] |
| +2.0 | M1 (`strong_beat_chord_tone_ratio`) [1] |
| +1.0 | M2 (`step_ratio`) [0.5] |
| +0.5 | `min(ioi_entropy / 2, 1)` |
| −1.5 | M3 (`repeat_ratio`) [0] |
| +1.0 | M5: recovered / leaps from `leap_recovery_counts` [1] |
| +1.0 | M11b (`motif_contour_match`) [0.5] |
| +1.0 | hook (`hook_restatements`) [0.5] |
| +1.0 | peak (`peak_uniqueness`) [0.5] |
| +1.0 | `max(contour_arch, 0)` [0] |
| +0.5 | `min(ambitus / 14, 1)` |
| −0.5 | `shape_moves` [0] |
| −3.0 | 1 if `final_fallback` |

**Interfaces:**
- Consumes: Task 1's candidates and `score_arrangement`. Feature 1's rendering (`humanize`, `build_midi`, `render_wav`, `render_plucked`).
- Produces:
  - `compose.ml.MLUnavailableError(RuntimeError)`. Its message names both `pip install -e ".[ml]"` and `music-decoder fetch-models --composer-models`.
  - `aesthetics.AestheticScorer` with a `score(wav_paths: Sequence[Path]) -> list[dict[str, float]]` method. It returns the axes `"CE"`, `"CU"`, `"PC"` and `"PQ"`. It is built by `aesthetics.load_scorer() -> AestheticScorer`, which raises `MLUnavailableError` when the package or the weights are missing, and runs on the CPU only.
  - `rank_by_audio(arrangements: Sequence[Arrangement], wav_paths: Sequence[Path], scorer) -> int`. It returns the index of the best.
    - The score is `(CE + PQ) / 2 + SYMBOLIC_WEIGHT * z`, with `SYMBOLIC_WEIGHT = 1.0`.
    - `z` is the candidate's symbolic score min-max normalised to [0, 1] across the K candidates; it is 0 when all are equal.
    - Ties go to the lowest index.
  - `compose_with_options(..., rank_audio=True)` for fingerstyle:
    - build the 12 candidates;
    - take the top `K = 4` by symbolic score;
    - render each to a temporary WAV with the composition's `sound`;
    - score them, choose one, and write only the chosen one.
    - `metadata["rank_audio"] = True` and `metadata["audio_scores"] = {"CE": …, "PQ": …}` for the chosen candidate.
    - For strum and arpeggio, `rank_audio` is ignored (`metadata["rank_audio"] = False`) and no model loads.
  - `arrange` therefore needs a way to return all candidates: `arrange_candidates(...) -> tuple[Arrangement, ...]`, sorted by symbolic score descending with ties going to the lower k. `arrange(candidates=n)` returns its first element.
  - `fetch-models --composer-models` calls `assets.fetch_audiobox()`, which downloads the repo snapshot into the Hugging Face cache. It prints the size.
